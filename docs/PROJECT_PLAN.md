# 无患影音项目计划

> 项目代号：无患影音（Wuhuan Player）  
> 当前工作分支：`wuhuan/development`  
> 主开发平台：Android 手机 / 平板；Android TV 后续阶段  
> 当前状态：源码基线审计与工程改造准备阶段

## 1. 产品目标

打造一款轻量、无广告、无强制会员、以本地播放和用户自配置内容源为核心的 Android 影音播放器。保留成熟播放内核与影视仓生态兼容能力，删除不需要的推广、遥测和原作者专属服务逻辑，形成清晰、可维护、可验证的独立产品。

### 产品原则

- 不内置、不捆绑、不暗中下载影视内容源。
- 不集成广告 SDK，不设置开屏广告、横幅广告、推广弹窗或强制会员入口。
- 默认不向第三方发送崩溃遥测、设备标识或使用行为数据。
- 本地媒体与用户主动配置的网络媒体是核心功能。
- 兼容能力以真实协议和测试结果为准，不以“支持影视仓”作无限承诺。
- 轻量不等于盲目删功能；每次删减都必须追踪调用链和回归验证。
- 所有改造在本仓库工作分支完成，不修改上游仓库及其默认分支。

## 2. 功能范围

### 2.1 第一阶段：Android 手机端

1. 本地媒体：系统文件选择器 / MediaStore 访问、本地视频播放、媒体信息、播放历史与续播。
2. 网络播放：用户粘贴或通过浏览器分享的媒体 URL；HTTP(S)、HLS、DASH 等由播放内核实际支持的流媒体协议。
3. 播放体验：常用音视频格式、字幕、音轨、倍速、画中画、手势与播放控制；具体格式能力以 Media3 解码器和设备能力为准。
4. 影视仓兼容：TVBox JSON 配置、分类、筛选、搜索、详情、播放线路及常见 CMS / Spider 接口；逐类验证兼容边界。
5. 用户数据：配置、历史、收藏等本地保存；提供清晰的数据导入导出与清理策略。
6. 隐私与安全：最小权限、透明网络请求、无第三方遥测、默认不自动更新。

### 2.2 后续阶段：Android TV

- 在手机端核心功能稳定后再恢复或重做 TV 界面。
- 适配遥控器焦点导航、远距离可读性、横屏布局和电视性能。
- 不把手机 UI 简单拉伸到电视屏幕。
- TV 构建与发布独立验收，不影响手机版本。

### 2.3 明确不纳入

- HarmonyOS / 鸿蒙版本。
- 内置影视资源、未经授权的内容分发或内容聚合服务。
- 广告变现、强制会员、开屏推广。
- 未经用户明确触发的第三方更新下载与安装。

## 3. 技术基线与许可证

- 暂定基于当前 Fork 的 `dev-5.6.1` 分支开展改造，工作分支为 `wuhuan/development`。
- 当前主播放内核为 AndroidX Media3 / ExoPlayer；MPV 已从该分支移除。
- 项目采用 GPL-3.0。分发衍生版本时，必须履行 GPL-3.0 的源码提供、许可证和版权声明等义务。
- 暂定沿用成熟的 TVBox / CatVod 兼容架构，但不默认承诺所有 Spider 运行环境均兼容。
- 所有依赖、AAR、Maven 仓库和运行时模块须记录来源、版本、许可证及必要性。

## 4. UI / UX 设计准则

### 4.1 视觉气质

关键词：**简洁、淡雅、清秀、博而不露、含而不发。**

- 追求清雅、有分寸、有余韵；避免大红大紫、强对比霓虹、厚重黑金和廉价“科技感”。
- 不靠毛玻璃、渐变、阴影或动效堆砌所谓高级感。
- 色彩以低饱和、柔和、耐看的中性色为基础；强调色少量使用，确保文字和控件对比度达标。
- 字体、图标、圆角、间距、层级和动效建立统一规范，细节经得起长期使用。
- 留白要有节奏，信息有疏密；不为极简而隐藏必要操作。
- 不堆砌古风纹样、书法字、装饰性中式符号；东方气韵应体现在克制与比例，而非贴标签。

### 4.2 信息架构与页面原则

- 首页：突出继续观看和最近播放；媒体库、影视源、搜索与设置分层清楚，不将海报铺成密集墙面。
- 本地媒体页：列表 / 网格可切换，文件信息明确，空状态和权限说明友好。
- 影视内容页：海报、标题、简介、年份、类型、线路等有明确层级，避免信息挤压。
- 播放页：画面优先、控制层收敛；播放进度、音轨、字幕、倍速等常用操作易于找到。
- 设置页：按任务分组，说明简短准确；高级选项有组织地收纳，不制造设置迷宫。
- 错误与空状态：解释发生了什么、用户可以做什么；不使用含糊或责备式提示。

### 4.3 设计验收标准

- 首屏能迅速识别当前内容和主要入口，不需要先读说明书。
- 常用播放操作路径短且一致；重要操作不因追求简洁而藏得过深。
- 页面没有无意义装饰、重复入口、拥挤海报墙或刺眼色块。
- 字体层级、间距、图标风格、圆角和颜色在全应用一致。
- 深色 / 浅色模式若实现，均须保持对比度、层次与视觉气质；不以纯黑铺满代替深色设计。
- 动效不阻塞操作；低端设备上不因模糊和复杂转场造成明显卡顿。
- 手机与 TV 分别设计、分别验收。

### 4.4 设计里程碑

1. 盘点现有页面、导航结构和可复用组件。
2. 定义颜色、字体、间距、图标、圆角和控件状态规范。
3. 完成首页与播放页的第一版视觉原型。
4. 对照实际源码评估实现成本，确认后再扩展到媒体库、影视详情和设置页。
5. 逐页实现并在真实 Android 设备截图验收。

## 5. 广告与隐私策略

- 不引入广告 SDK、广告展示位、推广弹窗或强制会员。
- 全仓检索统计、遥测、设备标识读取、远程配置和第三方网络请求。
- 移除原作者专属 Bugly 崩溃遥测及其 CI 符号表上传；如保留本地诊断日志，必须明确内容、保存位置、容量上限和清理机制。
- 移除原作者 GitHub / Gitee 更新检查、代理下载和安装入口；未来如需更新功能，单独设计用户主动触发、来源明确、签名校验的机制。
- 研究 WebView 广告域名拦截与 M3U8 广告切片识别。过滤必须可关闭、支持白名单；无法确定时优先不误删正片（fail-open）。
- 无法过滤已合并进视频画面的广告；不承诺“全网去广告”。
- 网络请求按功能列清单；默认不将播放地址、搜索记录或设备标识发送给无关第三方。

## 6. 权限策略

- 逐项追踪 Manifest 声明、合并 Manifest、运行时申请和实际调用点。
- 优先使用 Storage Access Framework / MediaStore，避免不必要的全盘文件访问。
- 移除 APK 更新后重新评估安装未知应用权限。
- HTTP 明文访问需兼顾用户自定义影视源兼容性；不能未经验证直接禁用。
- DLNA / SSDP、前台播放、通知等权限须由实际功能证明其必要性。
- 形成权限矩阵：权限、调用位置、用户场景、替代方案、保留/移除理由和验证方法。

## 7. 工程阶段与验收门槛

### 阶段 A：基线审计与工程准备
- 核对仓库、分支、许可证、构建环境、依赖和模块。
- 检索第三方 SDK、广告/统计/遥测、更新器、网络请求与设备标识。
- 追踪 Manifest 权限与 Spider 执行链路。
- 建立独立 CI，仅构建并上传 Actions Artifact，不创建/删除 Release，不上传 Bugly 数据。
- 验收：审计清单有代码位置和证据；工作分支与上游分支隔离。

### 阶段 B：产品外壳与视觉基线
- 确认应用名称、包名、图标、主题、导航和页面结构。
- 交付首页与播放页原型及设计规范。
- 验收：用户确认视觉方向；关键操作路径明确；不影响播放功能。

### 阶段 C：基础媒体播放
- 验证本地视频、外部媒体 URL、HTTP(S)、HLS / DASH、字幕、音轨、倍速、后台播放与画中画。
- 验收：真实设备测试矩阵通过；记录设备、系统版本、样本媒体、结果和日志。

### 阶段 D：影视仓兼容
- 验证 TVBox JSON、常见 CMS、CatVod Spider 和不同脚本运行环境。
- 将兼容性按已验证 / 部分验证 / 不支持分级。
- 验收：每类协议有可重复测试样例；失败能定位到配置、Spider、解析器或播放内核。

### 阶段 E：隐私、权限与广告处理
- 删除已确认无用的第三方遥测和原作者更新逻辑。
- 按权限矩阵收紧权限。
- 实现保守、可关闭、可白名单的广告过滤。
- 验收：无意外第三方遥测；核心功能权限最小化；过滤无明显误删正片。

### 阶段 F：稳定性与发布准备
- 完成构建、安装、升级覆盖、数据持久化、异常恢复和长时间播放测试。
- 检查 GPL-3.0 合规、第三方许可证、隐私说明与版本信息。
- 验收：构建产物可追溯；测试结果可复核；未验证事项明确列出。

## 8. 工作纪律

- 不以代码改动数量代表进度；每项改动对应问题、证据、验证。
- 先理解调用链再删依赖、权限或功能。
- 不宣称构建成功、问题修复或设备兼容，除非有实际日志或测试证据。
- 工具/环境受限时，明确区分已验证能力、当前限制、替代方案和未验证假设。
- 所有改动优先小步提交，提交信息说明目的；关键阶段保留可回退点。
- 不修改上游仓库、默认分支、原作者 Release / Tag。
